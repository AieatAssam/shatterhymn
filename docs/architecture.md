## 3. Runtime data flow

```
            pointer/keyboard
                  │
           input/input.ts ──(press/release/cancel, queued)──┐
                                                            ▼
 RAF ─► core/loop.ts ─(fixed 60 Hz ticks, respects freeze/timeScale)─► sim.step(input) ─► SimEvent[]
              ▲                                                                              │
              │ freeze(ms) / slowmo(scale, ms)                                               ▼
       render/juice.ts ◄────────────────────── core/events.ts (EventBus) ◄──── controller forwards
              │                                        │      │      │
              ▼                                        ▼      ▼      ▼
   render/* (reads sim.state each frame)        audio/*  haptics  ui/* (HUD, pop text, banners)
                                                                     │
                                         run end ─► meta/runEnd.ts ─► meta/save.ts (localStorage)
```

- **One source of truth:** `sim.state`. Render reads it every frame (positions, kinds, dial) and keeps its *own* visual-only state (shards, rings, springs) keyed by crystal id.
- **Events, not polling, for moments:** anything that should flash, sound or buzz is a `SimEvent`.
- **The sim is unaware of juice.** Freeze and slow-mo are presentation: `juice.ts` listens to events and calls `loop.freeze()` / `loop.slowmo()`. Because the sim counts ticks, freezes do not change outcomes (determinism holds).

## 4. Core modules

### 4.1 `core/rng.ts`
```ts
export function hash32(str: string): number {           // FNV-1a + murmur3 fmix32
  let h = 0x811c9dc5;
  for (let i = 0; i < str.length; i++) { h ^= str.charCodeAt(i); h = Math.imul(h, 0x01000193); }
  h ^= h >>> 16; h = Math.imul(h, 0x85ebca6b); h ^= h >>> 13; h = Math.imul(h, 0xc2b2ae35); h ^= h >>> 16;
  return h >>> 0;
}
export class Rng {
  constructor(public state: number) { this.state = state >>> 0; }
  next(): number {                                       // mulberry32, [0,1)
    let t = (this.state = (this.state + 0x6d2b79f5) >>> 0);
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  }
  range(a: number, b: number): number { return a + (b - a) * this.next(); }
  int(n: number): number { return Math.floor(this.next() * n); }      // 0..n-1
  sign(): 1 | -1 { return this.next() < 0.5 ? -1 : 1; }
  chance(p: number): boolean { return this.next() < p; }
  pick<T>(arr: readonly T[]): T { return arr[this.int(arr.length)]!; }
  weighted<T>(items: readonly { item: T; w: number }[]): T { /* sum, roll, walk */ }
  shuffle<T>(arr: T[]): T[] { /* Fisher–Yates in place, using this.int */ }
}
export function seedToHex(seed: number): string { return (seed >>> 0).toString(16).toUpperCase().padStart(8, '0'); }
export function hexToSeed(hex: string): number | null { /* /^[0-9a-fA-F]{8}$/ else null */ }
export function randomSeed(): number { /* crypto.getRandomValues(new Uint32Array(1))[0] */ }
```
`randomSeed` is the only function here that touches a browser API, and it is called only by the controller.

### 4.3 `core/loop.ts`
```ts
export const SIM_DT_MS = 1000 / 60;
export class Loop {
  constructor(opts: { now: () => number; tick: () => void; frame: (realDtMs: number, simDtMs: number) => void });
  start(): void; stop(): void;                // RAF; stop() cancels the RAF
  pumpFrame(nowMs: number): void;             // the RAF body; public for tests
  freeze(ms: number): void;                   // freezeUntil = max(freezeUntil, now + ms)
  slowmo(scale: number, holdMs: number, rampMs: number): void; // time scale = scale for holdMs, then linear ramp to 1 over rampMs (starts after any freeze)
  paused: boolean;                            // when true: no ticks, frame() still runs with simDt 0
  readonly timeScale: number; readonly frozen: boolean;
}
```
Per frame: `realDt = clamp(now - last, 0, 100)`; if paused or `now < freezeUntil` → `simDt = 0`; else `simDt = realDt × timeScale`; `acc += simDt`; `while (acc >= SIM_DT_MS && steps < 5) { tick(); acc -= SIM_DT_MS; steps++ }` (if 5 steps were hit, drop the remainder: `acc = 0`); then `frame(realDt, simDt)`. The render-side visuals (shards, rings) advance with `simDt` (so they hang in slow-mo and stop in freezes), except UI springs and the camera shake, which use `realDt`.

### 4.4 `core/spring.ts`, `ease.ts`, `noise.ts`, `date.ts`, `pool.ts`
- `Spring1D { x, v, target, f, zeta; step(dtSec) }`: semi-implicit Euler (style guide §6.3). Also `Spring2D`.
- `ease.ts`: `easeOutCubic, easeOutQuad, easeOutBack(s=1.70158), easeInOutSine, clamp01, lerp`.
- `noise.ts`: `valueNoise1D(seed: number, x: number): number` in [−1, 1], smoothstep-interpolated hashed lattice.
- `date.ts`: `localDateISO(d: Date): string` (`YYYY-MM-DD`, local time); `dailyNumber(iso: string): number` = whole days from `2026-10-27` + 1 (computed with `Date.UTC` on the parsed parts, so DST cannot shift it); `msToClock(ms): string` → `m:ss`.
- `pool.ts`: a generic fixed-size free-list pool.

### 5.3 `sim.ts`
```ts
export class Sim {
  constructor(opts: { seed: number; mode: RunMode; slowDial: boolean; script?: TutorialScript });
  readonly state: SimState;
  step(input: SimInput): readonly SimEvent[];    // advances exactly SIM_DT_MS; returns a reused array (copy if you keep it)
}
```
**Tick order (exact):**
1. If `over`, return no events.
2. Timers: `recoveryMs`, `jarMs`, `graceMs` decrease by dt (floor 0).
3. **Input → dial** (`dial.ts`): process `cancel` (drop the hold, no strike), then `press`, then `release` (→ `strike.ts`). This means a press and a release in the same tick give an instant strike on note 0.
4. **Dial advance:** while holding and not waiting for recovery, `stepElapsedMs += dt`; each time it passes `stepMs × (slowDial ? 1.35 : 1)`, advance the note and emit `dialStep`.
5. **Level:** `elapsedMs += dt` (not in tutorial/attract), recompute `level`, apply K changes, emit `levelUp`.
6. **Spawner** (`spawner.ts`): timer, formations, kinds, the cap and the fairness rules.
7. **Move crystals:** prism note cycling, splitter push, `rho`/`theta` update, `x = rho cos θ`, `y = rho sin θ`, `ageMs += dt`.
8. **Contacts:** in id order, resolve crystals whose `rho - r <= HALO_R`: grace hit or crack + flare (design §5), then game over check → emit `gameOver` (once) and set `over`.
9. `tick += 1`, `stats.timeMs = elapsedMs`.

Ids are assigned from a counter starting at 1 and never reused within a run. Crystal iteration is always in slot order, and slots are allocated lowest-free-first, so order is deterministic.

### 5.4 `dial.ts`, `strike.ts`, `spawner.ts`
- `dial.ts`: `pressDial(state)`, `releaseDial(state) → note | null`, `advanceDial(state, dt, stepMs, events)`. Rules: design §3.
- `strike.ts`: `resolveStrike(state, note, events, spawnChild)`: design §6 steps 1–10, in that order. Pure apart from the state mutation.
- `spawner.ts`: `class Spawner { constructor(rng); update(state, dt, events) }` holding the timer, tone bag, pending spiral queue and `lastMendMs`. Implements design §7.3–§7.5.

### 5.5 `tutorial.ts` and `attract.ts`
- `TutorialScript`: a list of steps (design §11) each with `spawns: {note, theta}[]`, `stopRho: 5`, `expect: 'press' | 'release' | {strikeNote:number} | 'button'`. In tutorial mode the spawner is replaced by the script, crystals stop at `rho = max(stopRho, rho)`, there is no contact or score. The controller advances steps on `strike` events / button presses and shows the text via `ui/tutorialOverlay.ts`.
- `attract.ts`: `AttractPilot` produces `SimInput` for the title screen: every 2.5 s it picks the note with the most targetable crystals, holds until the dial reaches it, and releases. Attract runs at L0 forever (level frozen), cracks disabled, and audio muted until the first user gesture.

### 6.2 API
```ts
export class AudioEngine {
  constructor(bus: EventBus, baseUrl: string);
  unlock(): Promise<void>;        // on the first pointerdown/keydown: create/resume AudioContext, decode the 26 mp3s (fetch + decodeAudioData), start music
  setVolumes(sfx: number, music: number): void; // 0..100, 40 ms ramps
  setScale(id: ScaleId): void;
  noteHz(note: number, octave?: number): number; // C5 × 2^(semitones/12) × 2^octave
  // event-driven: subscribes to bus events and calls these (also public for UI previews)
  playDial(note: number): void;
  playStrike(note: number): void;
  playShatter(note: number, n: number): void;    // glass sample tier + chord (style guide §8)
  playChoir(note: number): void;
  playClose(note: number): void;
  playDud(note: number): void;
  playCrack(): void; playMend(): void; playGameOver(): void; playNewBest(): void; playUnlock(): void;
  playUi(kind: 'click' | 'back' | 'toggle'): void;
  duck(db: number, attackMs: number, holdMs: number, releaseMs: number): void;
  suspend(): void; resume(): void;               // visibility
  readonly music: MusicEngine;
}
```
Rules:
- Every call is a no-op (no throw) before `unlock()` resolves or when the context is missing.
- **Voice cap:** 120 simultaneously alive oscillators. When exceeded, the oldest bell voice is released early (10 ms fade).
- Sample playback: an `AudioBufferSourceNode` → Gain → sfxBus; round-robin index per sample family; `playbackRate` per style guide §8.
- All scheduling uses `ctx.currentTime + 0.005` (+ stagger offsets for strums).
- On `visibilitychange` hidden → `ctx.suspend()`; visible → `ctx.resume()`.

### 6.3 `bellSynth.ts`
`playBell(ctx, dest, hz, when, gain, decayMul = 1, lowpassHz?: number): Voice`. Partials `[1, 2.0, 2.76, 5.40, 8.93]`, gains `[1, 0.45, 0.30, 0.16, 0.08]`, decays `[1.6, 1.1, 0.8, 0.45, 0.25] × decayMul` seconds. Envelope: `setValueAtTime(0)`, `linearRampToValueAtTime(g, when + 0.003)`, `exponentialRampToValueAtTime(0.0001, when + decay)`. Skip any partial above 16 kHz. Stop each oscillator at `when + decay + 0.05`.

### 6.4 `music.ts` — generative cathedral pad (no audio files)
- Tempo 72 BPM, 4/4. Bar = 3.333 s. Lookahead scheduler: `setInterval` 25 ms, schedule events ≤ 120 ms ahead.
- Chord cycle (scale-degree roots): `[0, 3, 1, 4]`, 2 bars each (an 8-bar loop). The chord on root degree d = degrees `d, d+2, d+4` (wrap to the next octave on overflow) of the current scale.
- **Layer A (always):** pad. For each chord tone, 2 detuned oscillators (`triangle`, ±6 cents) at octave 4 (C4 = 261.63 Hz base), through a lowpass at 1400 Hz (Q 0.7); per-chord crossfade 1.2 s; total gain 0.16. Plus the chord root an octave lower at gain 0.05 (for headphones).
- **Layer B (level ≥ 2):** chimes: on each beat, with probability 0.55, one bell voice (`playBell`, gain 0.05, decayMul 1.4) on a random chord tone at octave 6.
- **Layer C (level ≥ 4):** breath: every 2 bars, white noise → bandpass 1.2 kHz (Q 0.8), gain swell 0 → 0.05 → 0 over one bar.
- **Layer D (level ≥ 6):** 8th-note arpeggio up the chord tones at octave 5, bell gain 0.035, decayMul 0.5.
- Layers fade in/out over 2 bars when the level changes. Music uses its own `Math.random` (it's not gameplay).
- `slowDown()` (game over): schedule nothing new, ramp the pad's detune to −1200 cents and gain to 0 over 1.5 s. `restart()` on a new run.
- Title screen uses Layer A only.

## 9. Rendering (`src/render`)
- `renderer.ts`: `class GameRenderer { constructor(canvas, bus, getState: () => SimState, settings); frame(realDtMs, simDtMs); resize(); setTier(t); setSkin(id); setReducedMotion(b); dispose() }`. It owns the scene, camera and composer, and the sub-renderers below. Each sub-renderer has `update(state, simDt, realDt)` and listens to bus events for bursts.
- `crystals.ts`: 5 `InstancedMesh` (one per glyph shape) sized `MAX_CRYSTALS`. Each frame, writes instance matrices + attributes for alive crystals of that shape, sets `mesh.count`, and keeps visual-only state per id (flash, crack progress, spawn scale spring, "pending burst at time T" for freeze-then-burst and the Choir ripple). When the sim removes a crystal that has a pending burst, the renderer keeps drawing a **ghost** at its last position until the burst fires (ghost list, max 64).
- `shards.ts`, `sparks.ts`, `rings.ts`, `threads.ts`: preallocated pools; `burst(info, count)` API.
- `juice.ts`: subscribes to events, owns trauma, the bloom/CA/flash animators, camera fov spring, and calls `loop.freeze` / `loop.slowmo` per style guide §6.1. Reads the reduced-motion and shake settings.
- `quality.ts`: tier detection + the auto-tier controller (style guide §4.3).
- `glyphs.ts`: the 2D shape paths (shared by the extrude geometry, the DOM SVG icons and the share card).

## 10. UI (`src/ui`)
- `dom.ts`: `h(html: string): HTMLElement`, `qs`, `show/hide` (class `is-hidden`), and an `aria-live="polite"` announcer for banners.
- `hud.ts`: score (count-up), best, multiplier, hearts; spring-animated with `transform` only. Listens to `strike`, `crack`, `mend`, `newBestLive`, `gameOver`.
- `dialBar.ts`: the bottom dial; listens to `holdStart`, `dialStep`, `strike`, `dud`, `levelUp`.
- `popText.ts`: pool of 12 world-anchored labels; needs `project(x, y) → {sx, sy}` from the renderer.
- `banners.ts`: a queue; one banner at a time, 3 s each; the tip ids are stored in `save.progress.seenTips`.
- `screens/*`: each exports `mount(root, ctx)` and `unmount()`. The `ctx` carries the bus, save, controller actions and the audio engine (for previews).
- All screens are keyboard-reachable; buttons are real `<button>`s with text labels.

## 11. Game controller (`src/game/controller.ts`)
State machine: `boot → title ⇄ (tutorial | run | daily) → paused ⇄ run → over → (run | title)`.
- `startRun(mode, seed?)`: creates `new Sim(...)`, resets render pools, emits `runStart`, shows the HUD. First launch (`!save.progress.tutorialDone`) → tutorial first.
- Each tick: `sim.step(input.consume())` → forward events to the bus. Live PB check: when `state.stats.score > save.bests.score` for the first time this run (and the best is > 0), emit `newBestLive`.
- On `gameOver`: `runEnd.applyRunResult(save, result, todayISO)` → persist → after 1.4 s (style guide) mount results.
- `pause()`: `loop.paused = true`, `input.cancelHold()`, mount pause. `resume()`: 3-2-1 countdown (each 400 ms), then unpause.
- URL params on boot: `?seed=XXXXXXXX` → next Play uses that seed (title shows `Friend's seed XXXXXXXX`); `?daily=1` → title highlights the Daily Hymn button.

## 12. Meta (`src/meta`)

### 12.1 Save schema (localStorage key `shatterhymn:save`, JSON)
```ts
export interface SaveV1 {
  v: 1;
  settings: { sfx: number; music: number; vibration: boolean; reduceMotion: boolean | null /* null = follow OS */;
              slowDial: boolean; shake: number; tips: boolean };
  progress: { lifetimeShards: number; lifetimeChoirs: number; lifetimeCrystals: number; runs: number;
              daysPlayed: number; lastPlayedDate: string | null; tutorialDone: boolean;
              seenTips: string[]; seenKinds: Kind[] };
  bests: { score: number; biggestN: number; longestStreak: number; longestTimeMs: number };
  daily: Record<string /* YYYY-MM-DD */, { best: number; plays: number }>;  // keep the newest 60 dates
  missions: { date: string | null; ids: string[]; progress: Record<string, number>; done: string[]; bonusGiven: boolean };
  unlocks: { skins: string[]; scales: ScaleId[]; titles: string[] };
  equipped: { skin: string; scale: ScaleId; title: string };
}
```
Defaults: settings `{ sfx: 80, music: 60, vibration: true, reduceMotion: null, slowDial: false, shake: 100, tips: true }`; unlocks `{ skins: ['clear'], scales: ['bright'], titles: ['novice'] }`; equipped `{ skin: 'clear', scale: 'bright', title: 'novice' }`; everything else zero/empty/null/false.

Ids: skins `clear, quartz, rosegold, obsidian, aurora, rosewindow, crown`; scales `bright, dusk, koto, dream, gamelan`; titles `novice, chorister, cantor, bellwright, choirmaster, cathedral`.

`save.ts` API: `loadSave(storage): SaveV1` (parse → `migrate` → validate each field with defaults for anything missing or the wrong type; on a parse failure copy the raw text to `shatterhymn:save:corrupt` and return defaults), `writeSave(storage, save)` (try/catch; failures are ignored silently, e.g. Safari private mode), `scheduleWrite` (debounced 250 ms), `resetSave()`. `storage` is injected (a `Map`-backed fake in tests).

### 12.2 `runEnd.ts`
```ts
export interface RunResult { mode: RunMode; seed: number; stats: RunStats; hymn: number[]; slowDial: boolean }
export interface RunOutcome { newBest: boolean; prevBest: number; shardsEarned: number; missionShards: number;
  missionsCompleted: string[]; allMissionsBonus: boolean; unlocked: { kind: 'skin'|'scale'|'title'; id: string }[];
  dailyBest: number | null; nextUnlock: { kind: string; id: string; name: string; have: number; need: number } | null }
export function applyRunResult(save: SaveV1, r: RunResult, todayISO: string): RunOutcome; // mutates save; pure otherwise
```
Order: roll missions over if `save.missions.date !== todayISO` → bests → daily entry (if mode is daily) → days played (if `lastPlayedDate !== todayISO`) → lifetime counters (+ run shards) → missions progress → mission shards → unlock checks (shards, choirs, titles) → `nextUnlock`.

## 13. Build, PWA and deploy

### 13.1 `vite.config.ts`
- `base: './'`, `build.target: 'es2022'`, `build.assetsInlineLimit: 0` (keep audio as files), `test: { environment: 'node', include: ['tests/**/*.test.ts'] }`.
- Custom plugin `swPrecache()`: in `generateBundle`, collect every emitted file name of the bundle plus every file under `public/` (walk it with `node:fs`), compute `version = sha1(sorted list joined + each emitted asset's source length)` and emit `sw.js` as an asset with:
  - `const CACHE = 'shatterhymn-' + version.slice(0,10); const ASSETS = [ './', './index.html', ...files ];`
  - `install`: `caches.open(CACHE).then(c => c.addAll(ASSETS))`, then `self.skipWaiting()` is **not** called (the update waits until the next launch).
  - `activate`: delete caches whose name starts with `shatterhymn-` and isn't `CACHE`; `clients.claim()`.
  - `fetch` (GET, same origin only): cache-first, falling back to network; navigation requests fall back to the cached `./index.html`.
- Registration (`main.ts`, only `import.meta.env.PROD`): `navigator.serviceWorker.register('./sw.js')` after `load`. If `registration.waiting` exists (or appears via `updatefound`), the **title screen only** shows the banner `Update ready. Tap to refresh.` Tapping posts `{type:'skipWaiting'}` to the worker (the worker listens and calls `self.skipWaiting()`), then reloads on `controllerchange`.

### 13.3 Icons (`scripts/make-icons.mjs`, no dependencies)
Pure Node: rasterise per pixel with signed-distance functions (bell silhouette = union of a circle and a trapezoid; glow = `exp(-d*k)`; three note glyphs around it with glow) into an RGBA buffer, then encode PNG by hand (signature, IHDR, IDAT via `node:zlib.deflateSync` with a filter byte 0 per row, IEND, CRC32 table). Outputs 192, 512, maskable 512 (content inside the central 80%), and 180 (`apple-touch-icon.png`). The generated PNGs are committed to `public/icons/`; the build doesn't run the script.

### 13.4 GitHub Pages (`.github/workflows/deploy.yml`)
On push to `main` + `workflow_dispatch`: `actions/checkout@v4` → `actions/setup-node@v4` (node 22, cache npm) → `npm ci` → `npm run check` → `actions/configure-pages@v5` → `actions/upload-pages-artifact@v3` (path `dist`) → a deploy job with `actions/deploy-pages@v4`. ## 14. Performance rules
- No allocation per frame in sim, render or audio hot paths: reuse arrays, scratch `Vector3`/`Matrix4`/`Color`, and the event array.
- Instanced attributes: set `needsUpdate` only on attributes that changed this frame, with `setUsage(DynamicDrawUsage)`.
- DOM: HUD updates only on change; pop text uses `transform: translate3d()`; no layout reads in the frame loop after writes.
- `visibilitychange` hidden → pause the game, stop the loop (`loop.stop()`), suspend audio. Visible → restart the loop (the game stays paused until Resume).

## 15. Testing strategy
Everything under `core`, `sim` and `meta`, plus `haptics.ts` and `audio/scales.ts`, is unit-tested in Node. Render, audio graph and DOM are verified by `npm run build` succeeding and by code review against the style guide (no browser is available to the implementer). Each milestone in `milestones.md` lists its required tests. `npm run check` must pass at the end of every milestone.

### 20.2 Mode abstraction

```ts
export type ModeId = 'tap' | 'slice';
export interface ModeStart { seed: number; daily: boolean; profile: 'beginner' | 'standard'; slow: boolean; demo: boolean; gentleMiss: boolean }
export interface GameMode {
  readonly id: ModeId;
  start(opts: ModeStart): void;           // builds a new sim, resets render pools for this mode, shows its HUD
  tick(): void;                           // one fixed 60 Hz tick: drain input -> sim.step -> forward events to bus, renderer, HUD
  frame(realDtMs: number, simDtMs: number): void;
  setInputEnabled(on: boolean): void;
  readonly over: boolean;
  result(): { stats: MetaStats; hymn: number[]; seed: number } | null;
  qa(): QAModeState;                      // used by game/qa.ts only
  forceGameOver(): void;
  dispose(): void;
}
```

- The controller holds `active: GameMode | null` plus the attract `TapMode` used on the title. It handles screens, pause (3-2-1), game over → `applyRunResult` → results after 1.4 s, and the intro hand-over. It no longer touches `Sim` directly.
- Both sims emit events on the shared `EventBus`. Slice events use their own type names (`toss`, `cut`, `darkHit`, `strokeEnd`, `fall`); shared names (`choir`, `crack`, `levelUp`, `gameOver`) carry a `mode` field added by the mode when forwarding, so audio, haptics and the face can branch.
- `game/qa.ts` is imported only when `qa=1` (dynamic `import()`), so it is not in the normal path.

### 20.3 Input

- `#surface` receives `pointerdown/move/up/cancel` and `lostpointercapture`. In Tap, each `pointerdown` calls `onTap`; TapMode does the hit test in screen space (projection from the renderer) and queues a `SimInput`. In Slice, the first pointer opens a stroke; samples (coalesced) are normalised by `playArea.ts` and fed to `Blade`. On every tick SliceMode drains `Blade` into `SliceInput`.
- Timestamps come from `PointerEvent.timeStamp`. `Blade` and `SliceSim` receive them as numbers. Nothing in `src/sim` calls `performance`, `Date`, `window`, `document` or `Math.random` (the source test covers every file in `src/sim`).
- Title: pointer input goes to the DOM cards; the canvas does not take taps, except during the intro (any tap strikes).

### 20.4 Renderer

- `setMode('tap')`: tilted camera (§9), floor, halo, bell at the origin with face. `setMode('slice')`: `fitSliceCamera`, floor and halo hidden, bell at slice (W/2, .09) scaled to radius .075 H, face follows, blade ribbon on, halves pool on.
- New draw calls: face 1, motes 1, blade 1. Halves reuse the five crystal meshes through `aCut`.
- The renderer keeps reading the active mode's state through a getter; Tap state and Slice state are different types, so `GameRenderer` takes `getView(): RenderView` (a small union with `mode` and the fields the renderer needs).

### 20.5 Save and meta

`SaveV2` (MODES.md §10). `loadSave` always returns v2. `writeSave` writes v2 and, the first time a v1 text is replaced, copies it to `shatterhymn:save:v1`. `applyRunResult` updates the mode block and the shared parts.
